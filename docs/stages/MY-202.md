# MY-202 — `ledger list` stops re-reading unchanged files

Stage 1 of 2 · branch `goal2/desktop-ledger-list` · 2026-11-04 · local only (not pushed, no PR)

## Outcome

`FileLedgerStore.list()` returns the same ledgers, in the same order, with the
same diagnostics and the same no-writes rule, but a repeated scan re-reads and
re-parses only files whose stat identity changed. `load()` and the write CAS are
untouched and still read the real bytes.

## What changed

- `src/store/ledger.ts` — `list()` memoises the last successful read per file,
  keyed by a bigint stat fingerprint (`mtimeNs:size:ino`). A hit returns the
  memo; a miss re-reads. Absent and damaged files are never memoised, so a
  transient read error or a half-written file cannot stick, and diagnostics are
  recomputed every call. Names that left the directory are evicted. `publish()`
  drops the written file's entry after the atomic rename, so the store's own
  write is visible immediately. The legacy-table branch still runs every call.
- `test/ledger-list-cache.test.ts` (new) — counts `readFileSync` calls through a
  `vi.mock('node:fs')` wrapper that delegates to the real module. Covers: warm
  scan reads no `*.json`; another store's atomic rename is observed; a damaged
  ledger is re-read with its diagnostic while the good ledger is not; own write
  visible; legacy table re-read; deleted-then-recreated file re-read.

## Not in scope / still open

- `src/service.ts` still calls `list()` once per legacy run inside `restoreOf`
  (O(runs × ledgers) stats per view) and twice in `ledgers()`. Hoisting one
  snapshot per service call is a larger, separate change; this stage only
  removes the per-file read/parse cost.
- `list()` now hands the same readonly `Ledger` objects back across calls. All
  current callers only project them; a mutating caller would be a new bug.
- An in-place external rewrite that keeps `mtimeNs`, `size` and `ino` all
  identical would not be noticed. Every store write uses atomic rename, so its
  inode changes; the store never writes in place.
- Not pushed and no PR in this stage. Stage 2 pushes, opens a draft PR, waits for
  CI, runs the independent review and fixes blockers.
